# Stage 2 Metric Definitions

All calculations are deterministic over Stage 1 canonical ticket rows. Ticket ID remains the row grain. Source records are never removed. Numerical durations are elapsed minutes between UTC-normalized instants. Empty eligible populations produce null metrics, with zero eligibility counts.

| Metric | Meaning and formula | Eligible records / denominator | Source fields and policy |
|---|---|---|---|
| `attendance_flag` | Completed attendance indicator; true for status `resolved` or `closed`. | All tickets; completed count is resolved + closed. | `status`; policy defines auto-closed tickets as attendance. |
| `csat_response_flag` | A parseable integer score from 1 through 5, regardless of status, retained for source audit. | Primary `csat_response_count` and response rate include only valid responses on resolved/closed tickets. `csat_populated_valid_score_count` also reports the open/pending anomalies separately. | `csat_score`, `status`; survey is sent when ticket is resolved; blank means no response. |
| `mean_csat` and score counts | Arithmetic mean and counts by each 1–5 score. No score threshold percentage is inferred. | Valid 1–5 scores on completed tickets; denominator `csat_response_count`. | `csat_score`; policy's 1–5 survey. Valid populated open/pending scores remain visible and flagged but are excluded from primary performance CSAT. |
| `first_response_minutes` | Elapsed `created_at` to `first_response_at`. | Both timestamps parse, non-negative duration. Summary exposes `first_response_eligible_count`; mean and median use that count. | `created_at`, `first_response_at`; timestamp provenance from Stage 1. |
| `handle_time_minutes` | Elapsed `first_response_at` to `resolved_at` (never creation to resolution). | Completed ticket, both timestamps parse, non-negative duration. Summary exposes `handle_time_eligible_count`; mean, median, p75, p90 use that count. | `first_response_at`, `resolved_at`; policy handle-time definition. Percentiles use linear interpolation; no outlier removal. |
| `sla_target_minutes` | Channel target lookup: chat 15, voice 120, social 240, email 480. Voice represents the policy's voice callback channel. | Known channel with configured target. | `channel`; support-policy first-response targets, configured in `configs/config.yaml`. |
| `sla_status` / breach rate | First response elapsed from creation. `breached` only when response minutes are strictly greater than target; equality is `met`. | Requires known channel and valid non-negative creation-to-response duration. Missing/invalid timestamps and unknown channels are `not_evaluable`; breach rate = breaches / `sla_eligible_count`. | `created_at`, `first_response_at`, `channel`; policy targets. No credit economics are calculated. |
| Transfer metrics | `total_transfers` sums non-negative integer values; transferred ticket count has value > 0; rate = transferred tickets / tickets with valid transfer values. | Valid non-negative `transfers`; denominator exposed as `transfer_valid_count`. Completed-only average uses completed tickets with valid counts. | `transfers`; describes hand-offs without attribution. |
| Agent and assignment summaries | Apply the same ticket metric formulas grouped by `agent_id`, then separately by `agent_id` + effective team/tier/site/shift/date interval. | All metric-specific denominators are emitted in each group. Null roster context remains a distinct unmatched assignment group. | Resolver `agent_id`, Stage 1 effective roster attributes; never group by display name. |
| Period summaries | Full available population plus ticket-created calendar month and quarter in `Asia/Kolkata`. | Same metric-specific eligibility rules per period. | `created_at`; coverage is derived from observed data, not labeled as Q3 2026. |

No percentage-style CSAT threshold, agent ranking, tier comparison, causal inference, or performance score is defined at this stage.
